# 项目健康检查与精简 V1 — 需求设计文档

## 1. 背景

项目经过账号、聊天、拉黑、群管理、UI 重构和 AI NPC 多轮迭代后，已有一段时间未做整体维护。当前仓库存在状态文档失真、一次性调试程序长期保留、未使用前端组件和超大业务文件等问题，需要先恢复一个可信、简洁、可继续迭代的工程基线。

## 2. 目标

- 以当前代码、测试和 Git 状态为准，重新确认项目真实状态。
- 找出功能、工程、测试、安全、文档和发布层面的当前问题，并记录处理决策。
- 删除有明确证据证明不再被构建、文档或运行时引用的历史残留。
- 统一项目状态入口，避免 `ROADMAP.md` 与临时状态文件互相矛盾。
- 在不改变现有产品功能、协议和数据库结构的前提下完成精简。

## 3. 本期范围

### 3.1 仓库审查

- Git 分支、远端差异、工作区与提交状态。
- 后端、前端、Proto、部署配置、CI 和文档结构。
- 自动化测试、静态检查与前端生产构建。
- 大文件、重复职责、未使用代码、一次性工具和历史产物。

### 3.2 安全精简

- 删除未被任何脚本、文档或构建流程引用的一次性数据库/接口/聊天调试命令。
- 保留正式 API 入口和仍有明确用途的数据构造命令。
- 删除空的测试请求产物、未使用的 UI 组件和已失效的样式规则。
- 移除临时状态文档，将当前状态收敛到 Roadmap 和任务清单。
- 更新文档索引、README 和忽略规则，使目录用途可理解。

### 3.3 问题分级

- 本期修复：证据充分、风险低、可通过自动化验证的清理项。
- 后续重构：需要改变模块边界或大量回归的技术债。
- 发布前处理：需要运行环境、双账号联调或部署环境才能验证的事项。

### 3.4 审查中必须修复的问题

- 同一用户新连接替换旧连接后，旧连接的注销事件不得删除新连接。
- 广播清理慢客户端时不得在读锁下修改连接表。
- 连接表读写和在线人数统计必须通过一致的锁边界完成。
- 前端 WebSocket 地址必须使用已有的 `VITE_WS_BASE` 配置，并保留本地默认值。

## 4. 非目标

- 不新增产品功能。
- 不修改 Protobuf、数据库表结构或已有业务规则。
- 不在本期强拆 `Chat.jsx` 或 `chat_service.go`；二者需要独立重构和更完整的集成测试。
- 不在 Docker 服务不可用时伪造手工联调结论。

## 5. 用户场景

- 久未维护项目的开发者可以通过 README、Roadmap 和功能目录快速理解真实现状。
- 新的开发工作不再被过期调试程序、临时产物和重复状态说明干扰。
- 清理后所有现有自动化测试和构建结果与清理前一致。

## 6. 验收标准

- 一次性调试命令只在无引用证据成立时删除，`cmd/api` 和 `cmd/seed_social_data` 保留。
- 仓库不再跟踪空的 `test_register.pb`。
- 前端不再包含无引用的 `Separator` 组件和确认无引用的旧样式。
- 项目状态以 `docs/plans/ROADMAP.md` 为唯一状态总览，不再维护 `TEMP_STATUS.md`。
- 审查发现、已处理项和遗留项写入 `code-review.md`。
- WebSocket 重连替换和连接移除具有针对性回归测试。
- `cd backend && go test ./...`、`go vet ./...`、`cd frontend && npm test`、`npm run build` 全部通过。
- `ROADMAP.md` 与 `M0_TASKS.md` 同步本次结果。

## 7. 风险

- 历史调试命令可能存在未记录的个人使用方式；通过 Git 引用、文档引用和构建入口三重检查降低误删风险，需要时可从 Git 历史恢复。
- CSS 类可能被动态拼接；只删除能确认没有源代码引用的独立旧规则。
- 文档收敛会改变旧链接；同步更新仓库内全部引用。
