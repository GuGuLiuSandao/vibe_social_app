# 需求设计文档

## 1. 需求名称
- AI NPC 聊天能力 V1（MVP）

## 2. 背景
- 当前聊天侧已有两类主要入口：官方社区（固定话题房）与用户会话（私聊/群聊）。
- 需要新增第三类聊天能力：AI NPC 聊天，且在信息架构上与现有聊天类别同层。
- 长期目标是支持用户自定义 NPC 人设并拉人群聊；但本次先交付可上线的 MVP 版本。

## 3. 目标
- 在聊天列表中新增 AI NPC 类别，作为独立会话类型。
- MVP 固定 NPC 人设：`魔兽世界酒馆老板`，不开放用户自定义。
- MVP 仅支持用户与 NPC 单对单聊天。
- NPC 对用户具备跨 Session 长期记忆（断开连接、重登后仍能持续使用记忆）。

## 4. 用户价值
- 用户可以快速体验“角色化 AI 陪聊”而不依赖其他用户在线。
- 会话具备连续性，不会因重连或重新登录丢失互动上下文。
- 为后续“自定义 NPC + NPC 多人群聊（最多 4 人）”提供协议与数据层基础。

## 5. 功能范围
- 包含：
  - 新增会话类型：NPC（与官方群/群聊同层类别）
  - 新增默认 NPC 会话创建能力（MVP 固定角色）
  - 用户向 NPC 发消息后，服务端自动生成并回写 NPC 回复
  - NPC 回复通过 OpenAI 兼容 `chat/completions` 接口生成（可配置 API URL / API Key / Model）
  - NPC 记忆持久化（基于数据库），支持跨 Session
  - 前端聊天页新增 AI NPC 分类展示与一键发起入口
- 不包含：
  - 用户自定义 NPC 人设（名称、背景、语气、知识库）
  - NPC 邀请最多 4 人参与群聊
  - 多 NPC 并存与 NPC 商店/管理界面
  - 多模型路由编排（例如按成本/延迟自动切换供应商）

## 6. 核心流程
1. 用户在聊天页点击“AI NPC”入口。
2. 客户端发起创建 NPC 会话请求（若已存在则返回已存在会话）。
3. 用户发送文本消息。
4. 后端持久化用户消息 -> 更新 NPC 记忆 -> 生成 NPC 回复 -> 持久化 NPC 回复。
5. 前端实时看到 NPC 回复，退出/重登后历史消息与记忆仍生效。

## 7. 交互/业务规则
- 每个用户在 MVP 阶段仅有 1 个默认 NPC 会话。
- NPC 会话类型独立于私聊/群聊，不复用“关注关系”限制。
- NPC 会话禁止普通用户邀请他人（MVP 仅 1v1）。
- NPC 回复需保持“酒馆老板”角色语气（粗犷、接地气、招呼式）。
- 记忆以“用户维度”保存，最少支持昵称/偏好/近期关注话题等基础信息。

## 8. 验收标准
- 会话列表可看到 AI NPC 分类，能进入默认 NPC 会话。
- 发送消息后可收到 NPC 自动回复。
- 断开 WebSocket、重新登录后，NPC 仍可引用此前对话记忆。
- 不影响已有官方群聊、私聊、群聊主流程。
- 通过：
  - `cd backend && go test ./...`
  - `cd frontend && npm test`

## 9. 风险与待确认项
- 外部模型调用存在网络抖动与超时风险，需要降级策略（回退模板回复）。
- 需要补充审计、敏感词与成本控制。
- 需要在后续版本明确“长期记忆”的清理策略（过期、用户删除、合规导出）。
